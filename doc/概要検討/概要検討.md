# PC-8001無印 CP/M 2.2 動作プロジェクト 概要検討

---

## 1. 目的とスコープ

### 目的

PC-8001無印(以下「PC-8001」)でCP/M 2.2を起動・動作させる。SDカードをストレージとしたブート環境を構築し、あわせてSD作成ツールを整備する。

### スコープ前提

| 項目 | 対象 | 対象外 |
|------|------|--------|
| CP/Mバージョン | CP/M 2.2 | CP/M 3 (Plus)・MP/M |
| 文字セット | 英数モードのみ | 漢字・全角文字 |
| ストレージ | SDカードのみ | 実FDD・CMT・ROM |
| テキスト幅 | 80桁 | 40桁 |

### リポジトリの方針

本リポジトリにはCP/M本体ソース(CCP/BDOS)は含めない。取得元・ビルド方法を記録するにとどめ、PC-8001向けのBIOS、ローダ、ツール類のみを管理する。

## 2. ハードウェア構成

### 本体: PC-8001無印

| 項目 | 仕様 |
|------|------|
| CPU | μPD780(Z80互換) 4MHz |
| 標準RAM | 16KB(拡張で32KBまで) |
| ROM | N-BASIC 24KB(アドレス 0x0000〜) |
| CPU実速度 | メモリ1WAIT + CRTC/DMAのバス占有で実効 約1.84MHz相当 |
| テキスト画面 | 40桁/80桁 切替(本プロジェクトは80桁で使用) |
| CRTC / DMA | μPD3301(CRTC) + μPD8257(DMA)。DMAで本体RAMの画面領域をCRTCへ転送 |
| メインRAM配置 | 上位アドレス側(0x8000〜)に実装。最上位付近にテキストVRAMが存在 |
| テキストVRAM | **0xF300固定(N-BASIC時)**。使用域 0xF300〜0xFEB7(約3000バイト)。設定変更は可能 |

PC-8001の標準RAMは上位アドレス側に配置され、N-BASIC時はテキストVRAMが0xF300にマップされる。画面表示はDMA(μPD8257)が本体RAMの画面領域をCRTC(μPD3301)へ転送する方式で、転送中はCPUが停止する。CP/Mコンソール初期化時に80桁モードへ設定する前提とする。

### 増設メモリ: PC8001-MEM

- 128KB / 4バンク × 32KB 構成
- 切替対象は **0x0000〜0x7FFF(下位32KB)**。上位 0x8000〜0xFFFF は本体メインRAM(VRAM含む)が供給する。
- I/OポートE2/E3で制御(詳細は「3. メモリマップ設計」参照)
- リポジトリ: https://github.com/kuninet/PC8001-MEM

### SDブート方式(3方式)

以下の3方式を候補とする。詳細は「9. SDブート方式の比較と抽象化」で整理する。

1. **SD-DOS** (8255ビットバンギング)
2. **PC-8001_SD** (マイコン制御)
3. **Pico自作** (RP2040)

## 3. メモリマップ設計

### 課題

PC-8001は電源ON後 0x0000 からN-BASIC ROMが固定マッピングされる。CP/M 2.2はゼロページ(0x0000〜0x00FF)にRAMが必須であり、そのままではCP/Mを実行できない。

### 解決策: PC8001-MEM によるRAM切替

PC8001-MEMのI/Oポートを操作することで、N-BASIC ROMの下にRAMを切り替えられる。

| ポート | ビット | 機能 |
|--------|--------|------|
| E2 | bit0=0 | 0x0000〜の**読み出し**をN-BASIC ROMに割当 |
| E2 | bit0=1 | 0x0000〜の**読み出し**を拡張RAMに割当(ROMを隠す) |
| E2 | bit4=1 | 0x0000〜の拡張RAM**書き込み**を許可 |
| E3 | バンク選択 | 切替対象32KB窓のバンクを選択。リセット時はバンク0 |

**読み出し選択(bit0)と書き込み許可(bit4)は独立している**点が重要。bit4=1にすれば、ROMが読み出し側に見えている(bit0=0)状態でも、0x0000〜の拡張RAMへ書き込める。これを利用すると、ROMからの実行を続けながらゼロページ・低位RAMへCP/M本体を書き込み、準備完了後にbit0=1でROMを隠してRAM実行へ移行できる。

> E3のビット割当とバンク数の正確な表現(0〜3か0〜4か)、bit0/bit4以外のE2ビットの用途は実装で要確認(「13. 既知の課題」)。

### CP/Mが必要とする64KBアドレス空間の供給

CP/M 2.2はゼロページからメモリ上端までの連続した64KB空間を前提とする。本構成では2系統のRAMで供給する。

| アドレス範囲 | 供給元 | 用途 |
|--------------|--------|------|
| 0x0000〜0x7FFF | PC8001-MEM(32KB窓・バンク切替) | ゼロページ + TPA前半 |
| 0x8000〜0xF2FF | 本体メインRAM | TPA後半 + CCP/BDOS/BIOS(VRAM下端より下に配置) |
| 0xF300〜0xFEB7 | 本体メインRAM(テキストVRAM) | 画面表示用。CP/Mシステム領域は置けない |
| 0xFEB8〜0xFFFF | 本体メインRAM | 余白(ワーク等) |

CP/Mの慣例ではCCP/BDOS/BIOSはメモリ上端側に配置されるが、PC-8001ではN-BASIC時のテキストVRAMが0xF300〜に存在する。CP/Mでもこの画面領域はDMA転送元として使い続けるため、**CP/Mシステム領域(BIOS/BDOS/CCP)の上端はVRAM下端(0xF300)より下に置く必要がある**。すなわちCP/Mの実効メモリ上端は概ね 0xF2FF となる(VRAMアドレスは設定変更可能なため、配置を最適化する余地は設計フェーズで検討)。

### CP/Mメモリ配置(設計方針)

CP/M 2.2では各部のサイズが概ね決まっている(CCP=0x800/2KB、BDOS=0xE00/3.5KB は固定。BIOSは可変)。配置はアドレス昇順で以下の順序となる。具体的な先頭アドレスは上記VRAM制約を踏まえ**設計フェーズで確定(要確定)**。

```
低位 0x0000〜0x00FF  ゼロページ: RSTベクタ、JMP WBOOT(0x0000)、BDOSエントリ(0x0005)等
     0x0100〜        TPA (Transient Program Area): ユーザプログラム実行領域
        ↓(アドレス昇順)
        〜           CCP  (Console Command Processor, 2KB)
        〜           BDOS (Basic Disk Operating System, 3.5KB)
高位 〜(VRAM下端)    BIOS (Basic I/O System, PC-8001向け新規作成・可変)
```

### 128KBバンク活用方針(案)

切替対象は下位32KB窓のみのため、CP/M実行に常用するのはバンク0を想定。残りバンクはRAMディスクや、ウォームブート用のCCP/BDOS原本保持(「4. ブートシーケンス」「6. BIOS設計方針」参照)等への活用案がある。詳細は設計フェーズで検討する。

## 4. ブートシーケンス

以下は設計方針としての段階記述であり、詳細手順は設計フェーズで確定する。

**重要(ローダの実行位置):** ブートローダは切替対象である 0x0000〜0x7FFF では**なく**、切替の影響を受けない上位アドレス(0x8000〜の本体メインRAM、VRAM域を除く)で動作させる。これにより、ROM→RAM切替の瞬間にローダ自身が消える/化ける事故を避ける。

1. **電源ON** → N-BASIC ROMが 0x0000 から起動
2. **ローダ起動** → SD方式に応じた手段(拡張ROM/N-BASICからのロード/SD基板のブートROM 等。入口は方式依存=要確定)でブートローダを 0x8000〜の安全領域へ展開・実行
3. **CP/M本体をRAMへ書き込み** → E2 bit4=1(拡張RAM書込み許可)としたうえで、SDから読み出したCCP/BDOS/BIOSを所定アドレス(下位はバンク0のRAM、上位は本体RAM)へ転送。ROMは読み出し側に見えたまま(bit0=0)でよい
4. **ゼロページ初期化** → ゼロページ(0x0000: JMP WBOOT、0x0005: JMP BDOS、各RSTベクタ)を拡張RAMへ書き込む(bit4=1のまま)
5. **ROMを隠す(読み出しをRAMへ)** → E2 bit0=1 を設定し、0x0000〜の読み出しを拡張RAMへ切替
6. **BIOSコールドブートへジャンプ** → BIOS(BOOT)が周辺初期化・80桁モード設定を行い、CCPへ制御移行、CP/Mプロンプト表示

> ウォームブート(WBOOT)時のCCP/BDOS再ロード元(SDのシステムトラックから再読込するか、別バンクRAMに保持した原本から復元するか)は要決定(「6. BIOS設計方針」「13. 既知の課題」)。

> 参考: PC-8001は ESC+リセットで PC-8031系ディスクユニットのブートを試みる仕組みがある。SD基板がこの起動経路を模倣できるか(ブート初段の入口)は方式依存で要確定。

### ソースの入手

CCP/BDOSはDR社公開後にコミュニティが整備したソースを流用できる。主な参照先:

- **http://www.cpm.z80.de/** — The Unofficial CP/M Web Site。CP/M 2.2のオリジナルソースをzipで配布する一次的なアーカイブ(一時配布元)。

BIOSのみを新規作成し、CCP/BDOSは無改変または最小パッチでアセンブルする方針とする。なお無改変が成立するのはゼロページのBDOSエントリ・BIOSベース等のアドレス前提が一致する場合に限られ、構成に合わせた再配置(MOVCPM相当の処理)やパッチが必要になる可能性がある。

### ライセンス(要確認)

CP/M 2.2のソース/バイナリは、権利者の許諾のもとでコミュニティに配布されてきた経緯がある(古くはThe Unofficial CP/M Web Site経由での配布許諾、近年もDR/DOS, Inc.系の権利者による配布・改変の許諾に関する報道がある)。ただし**正確な許諾範囲・年・条件(再配布や表記の制約等)は配布元ごとに異なる**ため、利用前に各配布元(brouhaha/cpm22、Z80-Retro/cpm-2.2 等)のライセンス表記を確認する。本プロジェクト独自作成のBIOS・ローダ・ツール類のライセンスは別途定める(README参照)。

## 6. BIOS 設計方針

BIOSはPC-8001のハードウェア依存部であり、本プロジェクトで新規作成する。CP/M 2.2仕様の17エントリのジャンプテーブルを実装する。

### BIOSジャンプテーブル

| No. | エントリ名 | 役割 |
|-----|-----------|------|
| 0 | BOOT | コールドブート初期化 |
| 1 | WBOOT | ウォームブート(CP/Mリロード) |
| 2 | CONST | コンソール入力ステータス確認 |
| 3 | CONIN | コンソール1文字入力 |
| 4 | CONOUT | コンソール1文字出力 |
| 5 | LIST | リスト出力デバイスへ1文字出力 |
| 6 | PUNCH | パンチデバイスへ1文字出力 |
| 7 | READER | リーダデバイスから1文字入力 |
| 8 | HOME | ディスクトラック0へシーク |
| 9 | SELDSK | ディスク選択 |
| 10 | SETTRK | トラック番号設定 |
| 11 | SETSEC | セクタ番号設定 |
| 12 | SETDMA | DMAアドレス設定 |
| 13 | READ | セクタ読み込み |
| 14 | WRITE | セクタ書き込み |
| 15 | LISTST | リスト出力デバイスのステータス確認 |
| 16 | SECTRAN | 論理→物理セクタ変換 |

LIST、PUNCH、READERはPC-8001では実デバイスなし。ダミー実装とする方針。

### コールドブート/ウォームブート

- **BOOT(コールド)**: 初回起動時の周辺初期化。ブートシーケンス(「4.」)の最終段から呼ばれる。
- **WBOOT(ウォーム)**: TPA実行でCCP/BDOSが破壊された後に再ロードする。**再ロード元**は次のいずれかを設計フェーズで決定する(要決定):
  - SDのシステムトラック(DPBのOFFで予約した領域)から再読込する
  - PC8001-MEMの別バンクRAMにCCP/BDOS原本を保持しておき、そこから復元する

### ディスクI/O抽象化方針

BIOSのディスクI/O部(SELDSK/SETTRK/SETSEC/SETDMA/READ/WRITE)に「抽象化レイヤ(アダプタ層)」を設け、SDブートの3方式をドライバ差し替えで対応できる構造とする。詳細・方式比較は「9. SDブート方式の比較と抽象化」に集約する。第一実装方式の決定は「13. 既知の課題」で管理する。

## 7. ディスクサブシステム

### DPB (Disk Parameter Block)

CP/M 2.2のディスク管理はDPBで定義される。主要パラメータを以下に示す。具体的な値は設計フェーズで決定する**(要確定)**。

| パラメータ | 意味 |
|-----------|------|
| SPT | トラックあたりの論理セクタ数 |
| BSH | ブロックサイズシフト値 |
| BLM | ブロックマスク |
| EXM | エクステントマスク |
| DSM | ディスク最大ブロック番号 |
| DRM | ディレクトリエントリ最大番号 |
| AL0/AL1 | ディレクトリ使用ブロックのビットマップ |
| CKS | チェックサムベクタサイズ |
| OFF | システム予約トラック数 |

### セクタ変換・ブロッキング

CP/Mのセクタ単位は**128バイト**。SDカードのネイティブセクタは**512バイト**(=128B論理セクタ4個分)。BIOSのディスクドライバ内で512B↔128Bのブロッキング/デブロッキングを行う(設計方針)。

- **SECTRAN**(BIOS No.16, 論理→物理セクタ変換)と、512Bブロッキングは別概念。SDではインターリーブ不要のため**SECTRANは恒等変換でよい**見込みで、512B↔128Bの集約はREAD/WRITE側で扱う。
- **書き込みのread-modify-write**: 128B単位の書き込みでは、対象512Bセクタを一旦読み出し→該当128Bを差し替え→512Bを書き戻す処理が必要になる。性能・実装複雑度に影響するため、512Bバッファのキャッシュ方針を設計フェーズで検討する。

### ディスクイメージ形式

- SDカード上にCP/Mディスクイメージをセクタ列として配置する方針。
- FAT上のファイルとして配置するかRAW配置とするかは、採用するSD方式に依存するため後決定**(要確定)**。

## 8. コンソール/端末

### テキスト画面

PC-8001の80×25テキスト画面をCP/Mコンソールとして使用する。BIOSのCONOUT/CONINでVRAM(N-BASIC時 0xF300〜)を直接操作する方針。BIOSのBOOT(コールドブート)時に**CRTCを80桁モードへ初期化**する。

| 項目 | 値 |
|------|----|
| テキストVRAM | 0xF300〜0xFEB7(1行=表示80バイト+アトリビュート40バイト、最大25行) |
| CRTC(μPD3301) パラメータポート | 0x50 |
| CRTC(μPD3301) コマンドポート | 0x51(ICW/OCW) |
| 表示制御 | ポート0x40 の d3(/CLDS) |

CRTC初期化はポート0x51にICW:RESET→DMA設定→0x50へSCREEN FORMATパラメータ列→OCWで表示開始、という手順となる(詳細は設計フェーズ)。アトリビュートは1行40バイト(最大20組)で、文字単位ではなく桁範囲指定である点に注意。

### 端末エミュレーション

CP/Mアプリケーション(WordStar等)はADM-3A・VT52等の端末制御コードを前提とする場合が多い。BIOSのCONOUTでADM-3A/VT52相当のエスケープシーケンスを解釈・エミュレートする方針とする。

主なエスケープシーケンス対応方針:

- カーソル移動、消去、ホームポジション等
- 対応シーケンスの詳細は設計フェーズで確定

### キーボード

- 英数モードのみ対応。
- 制御キー(Ctrl+C, Ctrl+Z 等)・シフト処理を実装。
- 入力方式(ポーリング / 割り込み)は下記の割り込み方針とあわせて決定する。

### 割り込み・RST7

PC-8001はVRTC等による割り込み(RST7=0x0038)を使用する。CP/Mのゼロページにもベクタ域があるため、CP/M動作中の割り込み許可/禁止方針と、0x0038近辺ベクタの扱いを整理する必要がある(要確定)。当面はコンソール入力をポーリングで実装し、割り込みは原則禁止とする案を基本線とする。

### スクロール

ハードウェアスクロール機能の有無・実装方針は**要確定**。

## 9. SDブート方式の比較と抽象化

### 3方式の比較

| 方式 | 制御方式 | Z80側ドライバ負担 | PC連携 | 拡張性 | 動作実績(要確認) | ブート初段の入口(要確定) |
|------|---------|-----------------|--------|--------|------------------|--------------------------|
| SD-DOS | 8255 ビットバンギング | 大(SPI制御をZ80が直接実施) | FAT16でPC直接連携可 | 低 | 公開実績あり※ | 基板/付属ソフト由来の手段 |
| PC-8001_SD | MCU(Arduino等)制御 | 小(コマンド発行のみ) | MCU経由 | 中 | 公開実績あり※ | 付属の拡張ROM等 |
| Pico自作 | RP2040 | 小〜中(プロトコル設計次第) | 柔軟に設計可 | 高 | RC2014系で類似事例※ | 自作ファームで設計 |

※「動作実績」の列はPC-8001無印×CP/M用途での実績を断定するものではなく、各プロジェクトの公開情報に基づく参考。採用時に要検証。

### BIOS抽象化方針

BIOSのディスクI/F(SELDSK/SETTRK/SETSEC/SETDMA/READ/WRITE)を各方式のドライバに振り分けるアダプタ層を設ける。これにより特定方式への依存をBIOS本体から分離し、差し替え可能な構造とする。第一実装とするSD方式の決定は「13. 既知の課題」で管理する。
