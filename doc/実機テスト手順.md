# 実機テスト手順(#39 / CP-3)

PC-8001無印 + PC8001-MEM + chiqlappe/sdd 基板で CP/M 2.2 を起動するための実機検証手順。

## 1. 必要なもの

| 項目 | 備考 |
|------|------|
| PC-8001 無印 | μPD780(Z80互換) 4MHz |
| **PC8001-MEM** | 128KB拡張RAM(4バンク×32KB)。E2=拡張RAM制御, E3=バンク切替 |
| **sdd 基板**(chiqlappe) | microSD ドライブ。8255 + microSD カードソケット |
| **8KB拡張RAMボード**(chiqlappe/ram8k) | sdd の動作前提 |
| **拡張ROM**(2764/28C64 等) | ローダ(0x6000-0x7FFF)を焼く |
| microSD カード | 16MB以上の **SDSC/SDHC/SDXC**(MMC不可) |
| ROM ライター | Intel HEX `build/loader.hex` 書込用 |

## 2. ビルドと SDイメージの作成(ホスト側)

```sh
make setup        # 初回のみ(.venv + kosarev/z80 取得)
make fetch-cpm    # CP/M 本体ソース(brouhaha/cpm22)を取得
make bios         # build/bios.bin (2560B)
make cpm          # build/ccp.bin (2048B), build/bdos.bin (3584B)
make loader       # build/loader.bin (8192B), build/loader.hex (Intel HEX)
make cpm-image    # build/cpm-image.bin (8192B = LBA0-15 のシステム領域)

# SDイメージ作成
.venv/bin/python scripts/sd_tool.py mkimage --out build/sd.img
.venv/bin/python scripts/sd_tool.py sys --image build/sd.img \
    --bios build/bios.bin --ccp build/ccp.bin --bdos build/bdos.bin

# 任意: .COM ファイル投入
.venv/bin/python scripts/sd_tool.py put --image build/sd.img \
    --drive A --file MYAPP.COM

# microSD へ書き込み(macOS/Linux, デバイスは要確認・rdiskN 指定推奨)
sudo dd if=build/sd.img of=/dev/rdiskN bs=1m
```

`build/loader.hex` を ROM ライターで 2764/28C64 等に書き、拡張ROMソケットに挿入。

## 3. 起動シーケンス(実機)

1. SD カードを sdd 基板に挿入。
2. PC-8001 の電源を入れる(またはリセット)。
3. **CP-2 要確認: 拡張ROM 0x6000 への制御移行**
   - 拡張ROMがある状態で電源ONしたとき、N-BASIC ROM がどのタイミングで拡張ROMへ制御を渡すか、実機挙動を確認。必要なら N-BASIC からマニュアル起動するための手順(例: `MON` → `G 6000` 等)を準備。
4. ローダがSDからシステム領域(LBA 0-15)を読み込み:
   - LBA 0-4 → 0xE900(BIOS、2560B)
   - LBA 5-8 → 0xD300(CCP、2048B)
   - LBA 9-15 → 0xDB00(BDOS、3584B)
5. ROM隠蔽(E2 bit0=1)→ BIOS BOOT へ → サインオン表示 → CCPプロンプト `A>`。

## 4. CP-3 実機確認チェックリスト(オーナー対応)

エミュレータでは検証できない実機固有の値・挙動を以下で確認・記録してください。

### 4.1 CRTC(μPD3301)80桁モード ICW値

現在の `bios.asm` の BOOT は `OUT (51h), 0x00`(ICW: RESET)のみのスタブで、SCREEN FORMAT パラメータは未送出です。実機で正しく 80×25 表示するための ICW SCREEN FORMAT 1〜5 の値を確定する必要があります。

| 確認項目 | 期待 | 実機結果 |
|----------|------|----------|
| 1行の桁数(80桁モード) | 80 | |
| 1画面の行数 | 25 | |
| ICW SCREEN FORMAT 1(bit設定) | 要調査 | |
| ICW SCREEN FORMAT 2 | 要調査 | |
| ICW SCREEN FORMAT 3 | 要調査 | |
| ICW SCREEN FORMAT 4 | 要調査 | |
| ICW SCREEN FORMAT 5 | 要調査 | |
| DMA(μPD8257)設定値 | VRAM 0xF300〜0xFEB7 を1画面DMA転送 | |
| 表示制御(ポート0x40 d3=/CLDS) | 0で表示有効 | |

参考: N-BASIC の表示初期化ルーチンをディスアセンブルして同等の値を採用するのが確実。

### 4.2 キーマトリクス(ポート 0x00-0x09)

| 確認項目 | 結果 |
|----------|------|
| 押下時のビット極性 | 0=押下 / 1=押下 のどちらか |
| 行 × 列 → キーコード対応表(全体) | 別表として作成 |
| SHIFT キーの位置(行 bit) | |
| CTRL キーの位置(行 bit) | |
| RETURN, BS, ESC の位置 | |
| カナキー(本実装はカナ入力非対応) | 識別のみ |

現在 `bios.asm` の SCAN_KBD はダミーマッピング(行0 bit7=CTRL, bit6=SHIFT, 行r×8+col → ASCII 0x20+r*8+col)です。実機の正確なマトリクスに合わせて `SCAN_TO_ASCII` テーブルを書き換える必要があります。

### 4.3 sdd 基板の 8255 ポート確認

| 確認項目 | 期待 | 実機結果 |
|----------|------|----------|
| 8255 ベースI/Oポート | 0xFC(PA), 0xFD(PB), 0xFE(PC), 0xFF(CTL) | |
| 制御ワード | 0x88(MODE0/A=IN/B=OUT/CH=IN/CL=OUT) | |
| PB bit0 = CLK | OUT | |
| PB bit1 = MOSI | OUT | |
| PB bit2 = CS(負論理) | OUT | |
| PB bit3 = LED(負論理) | OUT | |
| PC bit4 = MISO | IN | |

SD-DOSと同一前提で実装済み。差異があれば `bios.asm` の `SD_INIT_PORTS` と `loader.asm` の `LD_SD_INIT_PORTS` の定数を更新。

### 4.4 起動シーケンスの動作確認

| ステップ | 期待 | 実機結果 |
|----------|------|----------|
| 拡張ROM 0x6000 起動 | ローダ実行開始 | |
| SD_INIT 成功 | ローダLEDが点灯/点滅 | |
| BIOS/CCP/BDOSロード | ~5秒前後 | |
| サインオン表示 | "PC-8001 CP/M 2.2 BIOS" が80桁画面に表示 | |
| CCP プロンプト | `A>` 表示 | |

## 6. 既知の制約と申し送り

- BIOS の `BOOT_DONE` は現状 HALT(雛形)。BIOS バイナリレイアウト(SIGNON+データ変数+`org 0EBE6h` の境界)の制約があり、コード追加が difficult。将来のリファクタで `BOOT_DONE → JP 0D300h` 化を行う(別 issue)。
- 半角カナの**入力**は未実装(表示は可能)。
- スタックは `BOOT` で `0DF00h`、`WBOOT_BODY` で `0F380h`(VRAM領域内・上から下成長で安全)。
- 詳細設計は `doc/設計/` 配下を参照。
